# 터미널 없이 쓰는 Codex 런처/GUI 기획서

작성일: 2026-06-21

## 1. 한 줄 정의

**Codex는 좋은데 터미널·로그인·명령어 때문에 못 쓰는 비개발자를 위한, 더블클릭 기반 Codex 런처/채팅 GUI.**

제품의 핵심은 Codex를 대체하는 것이 아니라, **Codex를 일반 사용자도 무섭지 않게 시작하고 사용할 수 있게 만드는 로컬 데스크톱 껍데기**다.

## 2. 문제 인식

개발자는 Codex를 터미널에서 알아서 쓴다. 그래서 이 제품의 핵심 고객은 개발자가 아니다.

진짜 고객은 다음과 같은 사람들이다.

- ChatGPT Plus 또는 AI 유료 서비스를 쓰고 있지만 Codex는 한 번도 못 눌러본 사람
- “터미널”, “명령어”, “로그인”, “폴더 경로”라는 말만 나와도 부담스러운 사람
- 컴퓨터 작업을 AI에게 맡기고 싶지만, 시작 과정이 너무 개발자스럽다고 느끼는 사람
- 40~60대 직장인, 자영업자, 교회/학원/모임 실무자, AI 초보자
- 투두TV 댓글에서 보이는 “흉내라도 내보고 싶은데 어렵다” 유형의 구독자

## 3. 사람들이 Codex를 못 쓰는 이유

성능이 부족해서가 아니라, 시작 과정이 너무 어렵다.

- 커맨드창/터미널을 열어야 한다.
- 명령어를 직접 입력해야 한다.
- 로그인 상태를 확인해야 한다.
- 로그인 안 되어 있으면 OAuth 흐름을 이해해야 한다.
- Codex CLI 설치 여부를 알아야 한다.
- 폴더 이동, 파일 경로, 에러 로그를 읽어야 한다.
- “내 컴퓨터가 망가지는 것 아닌가?”라는 불안감이 있다.

초보자에게는 Codex의 문제보다 **Codex 앞에 놓인 문턱**이 더 큰 문제다.

## 4. 제품 컨셉

사용자는 앱을 더블클릭한다.

앱은 자동으로 다음을 확인한다.

1. Codex CLI 설치 여부
2. OpenAI/Codex 로그인 상태
3. 작업 가능한 폴더 권한
4. 현재 세션 상태

로그인이 안 되어 있으면 앱이 공식 OAuth 로그인 페이지를 열어준다. 사용자는 공식 페이지에서 로그인한다. 앱은 비밀번호를 저장하지 않고, 로그인 완료 여부만 확인한다.

로그인이 끝나면 사용자는 터미널 화면이 아니라 **채팅형 UI**에서 Codex를 사용한다.

## 5. 사용자 경험 흐름

### 기존 흐름

```text
터미널 열기
→ 명령어 입력
→ 로그인 확인
→ 브라우저 로그인
→ 다시 터미널
→ 폴더 이동
→ Codex 실행
→ 에러 로그 확인
```

### 목표 흐름

```text
앱 더블클릭
→ 로그인 상태 자동 확인
→ 필요하면 공식 로그인 버튼 클릭
→ 작업 폴더 선택
→ 채팅창에서 Codex 사용
```

## 6. 핵심 UX 원칙

### 6-1. 비밀번호를 앱에 입력하지 않는다

앱은 OpenAI 아이디/비밀번호를 받지 않는다. 공식 로그인 페이지를 열고, 로그인 완료 여부만 감지한다.

화면 문구 예시:

> OpenAI 공식 로그인 페이지가 열립니다.  
> 비밀번호는 이 앱에 저장되지 않습니다.

### 6-2. 터미널 로그를 그대로 보여주지 않는다

내부적으로는 Codex CLI를 실행하더라도 사용자는 채팅 UI만 본다.

예:

- 터미널식: `ENOENT: no such file or directory`
- 사용자식: “해당 파일을 찾지 못했어요. 다른 폴더를 선택해볼까요?”

### 6-3. 작업 전 확인과 안전모드를 기본값으로 둔다

초보자에게 가장 중요한 것은 “AI가 내 파일을 마음대로 고치지 않는다”는 신뢰다.

기본값:

- 파일 수정 전 계획 먼저 보여주기
- 기존 파일 수정 전 백업 생성
- 새 파일 생성 우선
- 되돌리기 버튼 제공
- 위험한 명령은 사용자 확인 필요

### 6-4. 프롬프트보다 버튼을 먼저 보여준다

초보자는 빈 채팅창 앞에서도 막힌다. 그래서 시작 버튼이 필요하다.

예:

- 이 폴더 설명해줘
- 문서 요약해줘
- 파일 정리 계획 세워줘
- 오류 원인 쉽게 설명해줘
- README 만들어줘
- 수정 전 계획만 보여줘

## 10-1. 포터블 배포 원칙

이 제품은 설치형 앱보다 **포터블 ZIP 앱**이 더 적합하다. 타깃 사용자는 설치 과정, 관리자 권한, PATH, npm, 터미널 같은 단어에서 바로 이탈할 수 있기 때문이다.

기본 배포 형태:

```text
AI작업실_Portable.zip
→ 압축 풀기
→ AI작업실.exe 더블클릭
```

앱 폴더 구조 초안:

```text
AI작업실_Portable/
 ├─ AI작업실.exe
 ├─ updater.exe
 ├─ data/
 │   ├─ settings.json
 │   ├─ install-status.json
 │   ├─ license.json
 │   ├─ logs/
 │   ├─ backups/
 │   └─ sessions/
 ├─ skills/
 │   ├─ free/
 │   └─ pro/
 ├─ templates/
 └─ installer/
     ├─ check-runtime.ps1
     ├─ install-node.ps1
     ├─ install-codex.ps1
     └─ verify-login.ps1
```

원칙:

- 가능하면 관리자 권한 없이 실행한다.
- 설정, 로그, 백업, 세션은 앱 폴더의 `data/` 안에 둔다.
- 삭제는 폴더 삭제로 끝나게 한다.
- 사용자에게 `npm`, `PATH`, `CLI` 같은 단어를 기본 화면에서 노출하지 않는다.
- 고급 정보 보기에서만 기술 로그를 보여준다.

## 10-2. 첫 실행 설치도우미

v1의 핵심은 “앱만 포터블”이 아니라 **처음 실행할 때 필요한 준비를 앱이 대신 확인하고 안내하는 것**이다.

첫 실행 마법사 단계:

```text
1. Windows/인터넷 상태 확인
2. Node.js/npm 설치 여부 확인
3. Codex CLI 설치 여부 확인
4. Codex 로그인 상태 확인
5. 작업 폴더 선택
6. 테스트 실행
```

사용자에게 보이는 표현:

```text
AI 작업실 시작 준비

필요한 구성 요소를 확인하고 있어요.
복잡한 설정은 앱이 대신 처리합니다.
```

상태 표시 예시:

```text
✅ AI 작업실 앱
❌ AI 실행 엔진
❌ 로그인 연결
✅ 작업 폴더

[한 번에 준비하기]
```

내부적으로는 다음을 확인한다.

```powershell
node --version
npm --version
codex --version
```

하지만 사용자에게는 이렇게 표현한다.

- Node.js/npm → “AI 실행 준비 프로그램”
- Codex CLI → “AI 실행 엔진”
- `codex login` → “OpenAI 로그인 연결”
- PATH 오류 → “설치 위치를 찾지 못했어요”

## 10-3. npm/Node.js 처리 전략

목표는 사용자가 npm을 전혀 몰라도 되게 만드는 것이다.

v1 추천 방식:

```text
Node.js/npm/Codex 설치 여부 자동 점검
→ 없으면 공식 설치 버튼 제공
→ 설치 후 재확인
→ 로그인 연결
```

설치 후보 순서:

1. `winget` 사용 가능하면 Node.js LTS 공식 패키지 설치
2. `winget`이 없거나 막히면 Node.js 공식 설치 파일 다운로드 안내
3. 회사/학교 PC 권한 문제면 수동 설치 가이드와 진단 파일 제공

사용자 문구:

```text
AI 실행 엔진을 사용하려면 준비 프로그램이 필요해요.
아래 버튼을 누르면 공식 설치 파일로 안전하게 준비합니다.

[AI 실행 준비하기]
```

실패 문구는 원본 npm 오류를 그대로 보여주지 않는다.

나쁜 예:

```text
npm ERR! code EACCES
```

좋은 예:

```text
설치 권한 때문에 자동 설치가 막혔어요.

가능한 이유:
- 회사/학교 PC에서 설치 권한이 제한됨
- 백신 프로그램이 차단함
- 인터넷 연결 문제

[다시 시도]
[수동 설치 안내]
[진단 파일 만들기]
```

## 10-4. 포터블 런타임 번들 전략

처음부터 Node.js와 Codex까지 모두 앱에 포함하면 UX는 가장 좋지만, 재배포 약관/보안 업데이트/로그인 세션 위치 문제가 생길 수 있다. 따라서 단계적으로 간다.

권장 로드맵:

```text
v1: 포터블 앱 + 공식 설치도우미
v2: 설치 실패 자동 진단 + 수동 가이드 강화
v3: portable Node.js 번들 검토
v4: 검증된 런타임/스킬팩 자동 업데이트 + Pro 기능
```

v1에서는 Codex 자체를 몰래 번들하지 않는다. 대신 “OpenAI 공식 설치 프로그램을 실행합니다”라고 명확히 안내한다.


## 11. 경쟁/대체재와 차이

### Cursor와 다름

Cursor는 개발자용 IDE다. 이 제품은 비개발자용 Codex 실행기다.

### ChatGPT 웹과 다름

ChatGPT 웹은 대화 중심이다. 이 제품은 사용자의 로컬 폴더/파일 작업을 Codex로 실행하게 돕는 런처다.

### 터미널 Codex와 다름

터미널 Codex는 개발자에게 빠르다. 이 제품은 초보자에게 안전하고 덜 무섭다.

## 14. 수익화 가능성

이 제품의 과금 포인트는 AI 모델 사용료가 아니라 **편의성, 안전성, 초보자 UX**다.

가능한 유료 기능:

- 프리셋 작업 버튼
- 자동 백업
- 되돌리기
- 작업 기록 저장
- 한국어 에러 설명
- 쉬운 템플릿 업데이트
- 초보자용 작업 예제팩
- 원클릭 업데이트

초기 가격 가설:

- 무료: 기본 실행/로그인 확인/기본 채팅
- 유료: 월 4,900원~9,900원 수준의 편의 기능

### v1~v4 무료/유료 전략

추천은 v1~v3까지 무료로 신뢰와 사용 습관을 만들고, v4부터 Pro 스킬팩과 자동 업데이트로 유료화하는 것이다.

```text
v1 무료: 포터블 앱 + 설치도우미 + 기본 채팅 + 기본 스킬 3개
v2 무료: 폴더 선택/저장/복사/최근 작업/쉬운 안내 강화
v3 무료: 수정 전 미리보기 + 자동 백업 + 되돌리기 + 작업 기록
v4 Pro: 업무 스킬팩 + Pro 템플릿 + 자동 업데이트 + 고급 진단/복구
```

주의: **설치도우미 자체를 유료로 막으면 안 된다.** 진입 장벽을 낮추는 기능은 무료여야 한다. 돈을 받는 대상은 “업무 시간을 줄이는 스킬팩/템플릿/업데이트/고급 안전기능”이다.

Pro 기능 예시:

- 보고서 자동 초안 스킬팩
- 회의록 정리 스킬팩
- 유튜브 대본/블로그 변환 스킬팩
- 엑셀/CSV 요약 스킬팩
- Pro 스킬 자동 업데이트
- 설치 문제 자동 진단 리포트
- 백업/복구 고급 기능

## 16. 검증 방법

앱을 만들기 전에 투두TV 콘텐츠로 수요를 확인한다.

영상/커뮤니티 질문 예시:

```text
Codex가 좋은 건 알겠는데 터미널 때문에 못 쓰셨나요?

제가 더블클릭하면 로그인 확인부터 채팅창 실행까지 되는
초보자용 Codex 도우미를 만들어보려고 합니다.

필요하신 분은 댓글에 “Codex 도우미”라고 남겨주세요.
먼저 테스트 버전 보내드리겠습니다.
```

검증 기준:

- 댓글 20개 이상
- 실제 테스트 희망자 5명 이상
- 화면 녹화 데모 요청 3명 이상
- “어디서 받을 수 있나요?” 반응이 나오면 MVP 제작

## 17. 첫 데모 시나리오

1. 앱 더블클릭
2. “Codex 설치 확인 중” 표시
3. “로그인이 필요합니다” 안내
4. 공식 OpenAI 로그인 페이지 열기
5. 로그인 완료 후 앱으로 복귀
6. 샘플 폴더 선택
7. “이 폴더 안의 파일을 쉽게 설명해줘” 입력
8. Codex가 채팅 UI로 결과 표시
9. 수정 작업 전에는 “계획만 보여주기”로 안전하게 종료

## 18. 결론

이 아이디어의 본질은 “개발자를 위한 더 좋은 터미널”이 아니다.

개발자는 이미 터미널에서 알아서 한다.

진짜 기회는 **터미널 앞에서 멈추는 일반 사용자**에게 있다.

따라서 제품 방향은 다음 한 문장으로 정리된다.

> Codex를 개발자 도구에서 일반인도 더블클릭으로 시작할 수 있는 안전한 AI 작업실로 바꾼다.
